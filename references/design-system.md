# 视觉与工程规范

## 一、画布与安全区

```
1080 × 1920（9:16）
├─ 顶部 172px   状态栏 + 系列名 HUD
├─ 左右 96px    内容边距
└─ 底部 360px   抖音文案/音乐条覆盖区 —— 任何文字不得进入
```

底部 360px 是硬约束。`qa.mjs` 的 `safe-bottom` 就是量这条线。

**这三个数字只写在模板的 CSS 变量里**（`--pad-x` / `--safe-top` / `--safe-bottom`），
`qa.mjs` 运行时从页面读回来。改安全区只改模板一处，不要在两处各写一遍。

## 二、字体白名单（只有两款）

| 字体 | 权重 | 用途 | 文件 |
|---|---|---|---|
| `LXGW WenKai GB` | 500 | 标题、引文、大数字 | `assets/fonts/kai500.ttf` |
| `Noto Sans SC` | 500（默认）/ 300 | 正文、标签、HUD；300 只在刻意做极淡装饰时用 | `assets/fonts/hei500.otf`、`hei300.otf` |

三条硬规则：

1. **不得引入第三种字体**，包括系统默认（`sans-serif` 会 fallback 到微软雅黑）。
2. **`font-weight` 必须与 `@font-face` 声明完全一致**（楷体只有 500）。写 `400` 会静默回退成黑体 —— 这是最隐蔽的 bug。
3. **必须 `document.fonts.load()` 显式等待三个字重**，否则首帧用回退字形渲染，之后不再重绘。

字体已用 GB2312 + 常用符号子集化（19MB → 3.4MB），SIL OFL 1.1，可商用。

## 三、色彩

| 变量 | 值 | 用途 |
|---|---|---|
| `--bg-core` | `#16110C` | 中心暖夜 |
| `--bg-mid` | `#0A090C` | 过渡 |
| `--bg-edge` | `#050507` | 边缘压暗 |
| `--ink` | `#F4EFE6` | 主文字（暖白，不用纯白）17:1 |
| `--ink-2` | `#E2DCCE` | 正文、说明 14:1 |
| `--ink-dim` | `#C9C2B2` | 出处、单位、HUD 11:1 |
| `--gold` | `#E0A94E` | 强调色，`<em>`、数字、图形 9.3:1 |
| `--cyan` | `#5FD0C8` | 次强调，仅用于对比点 |

**金色占比 ≤ 8% 画面**。金色一多，贵气立刻变土气。

**文字对比度是硬指标，不是审美偏好**：小字（< 48px）在手机上还要过一遍抖音压缩，
深底暗字会直接糊掉。判据写进 `qa.mjs` 的 `low-contrast`：

| 字号 | 最低对比度（相对 `#0B0C10` 底色） |
|---|---|
| < 48px（kicker / unit / cite / label / HUD） | **9 : 1** |
| ≥ 48px（title / body / quote / num） | 4.5 : 1 |

三条配套铁律：

1. **小字不许用 300 字重**。细笔画在深底上层，缩放和压缩后第一句先烂——最小字重 500。
2. **降级靠字号和字重，不靠把颜色调暗**。需要"次要"就用更小的字号，不要用更暗的灰。
3. 对比不够时，先提亮颜色变量，再考虑加字号；**不要加描边或阴影**，压缩会变成噪点。

## 四、字号阶梯

| 元素 | 字号 | 行高 |
|---|---|---|
| `.num` 大数字 | 300px | 1.0 |
| `.qmark` 引号 | 200px | 0.66 |
| `.title` 标题 | 128px（自动降到 ≥56） | 1.26 |
| `.qtext` 引文 | 76px（自动降到 ≥42） | 1.72 |
| `.body` 正文 | 40px | 1.9 |
| `.label` 说明 | 36px | 1.8 |
| `.unit` 单位 | 38px | — |
| `.kicker` 小标 | 25px，字距 .28em | — |
| `.cite` 出处 | 23px，字距 .16em | — |

标题自动缩字号公式：`px = clamp(888 / (em宽度 × 1.04), 56, base)`。
**低于 56px 就不该再缩了，该删字。**（`build.mjs` 就是这么判的）

## 五、版面骨架

全部**绝对定位**，不用 flex 流式布局：

```
.scene
 ├─ .kicker   绝对定位 top:172  left:96
 ├─ .stack    绝对定位 top:172 bottom:360，内部 flex 纵向居中
 └─ canvas#fx 绝对定位全屏，图形自己算坐标
```

为什么不用流式：`margin-top:auto` 之类的自适应会在内容变长时把元素推出安全区，
而且推出去的方向不可预测。绝对定位 + 显式分区，问题只会在一个方向发生。

带图形的场景，`.stack` 加 `.top`：文字压在上半区，图形占下半区
（图形基线 `H*0.745`，顶部 `H*0.535`），两侧互不侵占。

## 六、分行与宽度控制

分行全部是**手动**的（`\n` → 每行一个 `<span class="ln"><b>…</b></span>`），
所以必须同时做两件事，缺一个就会二次折断——标题被拦腰折成两截就是这么来的：

1. **行内元素 `white-space:nowrap`**：否则容器的 `max-width` 会在你以为排好的位置上再折一次。
2. **宽度只由字号控制**：需要更窄就降字号，**不要收 `max-width`**（一收就会折，且折点不可控）。

标题字号按最长行反推，留 3% 余量（`letter-spacing` 不参与字数/宽度估算，每行会累积 `0.01em × 字数`）：

```
px = min(base, floor(container / 最长行em宽 * 0.97))
```

`em宽` 按中文 1、拉丁 0.56 累加。低于 100px 就说明该删字了，不该继续缩。

## 七、动效时间轴（场景内 p ∈ [0,1]）

| 元素 | 出现区间 | 效果 |
|---|---|---|
| 场景整体 | 0–0.055 淡入 / 0.94–1 淡出 | opacity + 轻微 scale |
| `.kicker` | 0.00–0.12 | 上移 16px + 模糊 |
| 标题逐字 | 0.03–0.34 | 每字延迟，上移 30px + blur 16px |
| `.body` | 0.30–0.50 | 上移 24px |
| `.cite` | 0.58–0.76 | 上移 14px |
| 图形 | 0.05–0.72 | 按类型 |

**场景切换不得留空档**：淡入必须 ≤ 5.5% 场景时长，否则出现黑屏（`qa --video` 会报 `black-frame`）。

## 八、图形层（canvas 1080×1920）

| 类型 | 参数 | 视觉 |
|---|---|---|
| `particles` | `n`, `seed` | 缓慢上升的粒子，全屏环境层。**不参与安全区约束** |
| `grid` | `cols`, `rows`, `cell`, `gap`, `highlight` | 方格逐个点亮，第 highlight 个金色脉冲 |
| `curve` | `kind: entropy` | 香农熵曲线，带扫掠进度、切线、当前点读数 |
| `flow` | — | 四点闭环贝塞尔回路，虚线流动 |
| `bars` | `n` | 中间高两侧低的高斯分布柱 |

图形必须满足：**底部不越过 `H - 360`**，顶部不高于正文底部。

## 九、HUD

左上是 `● 系列名 / @账号`，右上是两位编号（自动按场景递增），
底部 2px 渐变进度条。这三样是「系列感」的来源，不要删。

## 十、渲染参数

| 项 | 值 | 说明 |
|---|---|---|
| 分辨率 | 1080×1920 | 抖音竖屏标准 |
| 帧率 | 30fps | 60fps 收益不抵体积 |
| 编码 | libx264 / CRF 18 / yuv420p | 兼容性优先 |
| 音频 | AAC 192k | 无 BGM 时补静音轨，避免部分播放器异常 |
| 单帧耗时 | ~270ms（含 40ms 稳定等待） | 45s 片约 7 分钟 |

**20 秒以内可全帧渲染；超过 40 秒先用 `--step 90` 抽帧试片**（体积小、速度快），
确认无误再全量。

## 十二、横屏 1920×1080 的安全区（与竖屏完全不同，不要套用）

竖屏的「左右 96、底部 360」在横屏上全错。横屏实测值：

| 边 | 值 | 原因 |
|---|---|---|
| 左 | **120** | 横屏左侧无遮挡，可以贴紧 |
| 右 | **180** | 右侧点赞/评论/分享按钮列实占 150–175px，内容必须 x ≤ 1740 |
| 上 | **96** | 顶部标题/搜索条 |
| 下 | **140** | 底部文案 + 进度条 |

两条容易忽略的推论：

1. **横屏的居中轴是 x=900，不是 960。** 右侧 UI 在视觉上压了 60px 的重量，对称轴左移 60，
   画面在手机上才"看着是正的"。
2. **页脚不要用 `bottom` 定位。** 竖屏模板里 `bottom: calc(--pad-bottom - 54px)` 算出 y≈1008，
   在横屏上会直接躺在抖音进度条底下；横屏要改成 `top: 890px` 这种顶锚定。

字号阶梯也要整体换一套：横屏主标题 **152px**、居中大标题卡 **200px**、正文 **42px / 行高 1.62**。
竖屏的 128px / 40px / 1.9 是给 9:16 的窄屏定的，套到 16:9 上会显得整屏都在"飘"。

### 这套规范已落成模板：`assets/template-wide.html`

不要再照着上面的数字手写横屏版式——直接用模板（`--aspect wide` 自动选用）。
模板里的关键常量：

| 项 | 值 | 说明 |
|---|---|---|
| `--pad-x` / `--pad-right` | 120 / 180 | `qa.mjs` 读的就是这两个变量名 |
| `--safe-top` / `--safe-bottom` | 96 / 140 | 同上，qa 靠它们判越界 |
| 正文行高 | 1.62 | 单行 68 / 78px，两行约 136–156px |
| 版式 | `split` / `center` / `data` / `vert` / `formula` | 各自独立定位，见模板 CSS |

**实测踩到的两个越界点**（都已修，但同类版式新增时要照着算）：

1. `center` / `data` 版式的正文原来 `top:800px`，两行 48px×1.62 ⇒ 底部 956px，
   越过 940 的安全线 16px。改成 **776px**（两行底边 932）。
2. `formula` 版式正文原来 `top:870px`，两行 ⇒ 底部 1006px，**超 68px**，
   第二行直接落在抖音进度条下面。改成 **800px**。

通用算式：`top + 行数 × 字号 × 1.62 ≤ 1080 − 140`。
横屏正文最容易出错的地方不是宽度，是**两行比一行多出整整 78px**——按一行算位置，
两行必然越界。
