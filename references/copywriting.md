# 文案改写规范

用户给的是「一段文案」，要变成「七屏画面」。这不是翻译，是**重排信息密度**。

## 一、先做减法：一屏只留一个主张

原文往往一句里有三个意思。拆：

```
原文：算法的推荐机制其实是在不断缩小你接触新信息的可能性，所以越用越窄。

拆成两屏：
S4 算法喂给你的 / 是你已经知道的
   推荐越准，你收到的 / 新信息越趋近于零。
S5 越确定 / 越没有信息
   一件事概率越高，/ 它告诉你的事情越少。
```

判断标准：**这一屏，观众能一句话复述出来吗？** 不能就再拆。

## 二、钩子公式（`hook`，4–5 秒）

前 3 秒决定划走率。四种可用句式：

| 句式 | 例 |
|---|---|
| 反常识断言 | 你刷到的每一条，都是你猜不到的 |
| 数字落差 | 8 个格子，藏 1 个数字，只要 3 次就能猜中 |
| 归因错位 | 你以为你在选内容，其实是内容在选你 |
| 代价揭示 | 你每天刷 2 小时，收到的新信息可能为零 |

**禁用**：「大家好」「今天我们来聊聊」「你知道吗」（问句开场留客率低于断言）。

## 三、节奏公式

单屏 `dur` 与字数强相关，按 **5–6 字/秒** 估：

| 该屏文字总量 | 建议 dur |
|---|---|
| ≤ 15 字 | 4.0–5.0s |
| 16–30 字 | 5.5–6.5s |
| 31–45 字 | 7.0–8.0s |
| > 45 字 | 必须拆屏 |

节奏要有起伏，不要全是 6s：**钩子短 → 命题稳 → 展开加速 → 落点放慢**。

## 四、句式改写四条

1. **抽象名词 → 具体动作**
   `信息熵较高` → `一条你猜不到的消息`
2. **长定语拆成短句**
   `那些被算法不断强化你已经相信的东西的内容` → `算法喂给你的，是你已经知道的`
3. **删掉连接词**
   `因此` `所以` `事实上` `不得不说` 全部删除，靠分行制造因果
4. **数字必须落地**
   `大量` → `8 个`；`很高` → `3 比特`

## 五、断行规则（比字号更重要）

`body` 用 `\n` 手动断行，**断在语义停顿处，不断在词中间**：

```
好：推荐越准，你收到的 / 新信息，越趋近于零。
坏：推荐越准，你收到的新信 / 息，越趋近于零。
```

每行 ≤ 20 字（正文）/ 12 字（标题）。两行长度差控制在 30% 以内，画面才平衡。

## 六、`<em>` 的使用

一屏最多 1 处，标在**反转词**上，不标在主语上。

```
对：都是<em>猜不到</em>的
错：<em>你</em>刷到的每一条
```

## 七、引文（`quote`）

引文是给画面「换个气口」的，不是炫学。要求：

- 真有一句可引的原话（不要编造出处）
- ≤ 3 行 × 12 字
- `cite` 只写来源名，≤ 26 字符宽度

没有合适引文时，**直接跳过 quote 场景**，不要硬凑。

## 八、收尾（`outro`）

一句可执行的话 + 一句出处/标题。不要「点赞关注」「我们下期见」。

```
对：去看不懂的书，见想法不同的人。
错：如果觉得有收获，记得点赞关注！
```

## 九、完整改写示例

输入：

> 香农在 1948 年提出信息论，他认为信息量不是由字数决定的，而是由不确定性决定的。一个事件发生的概率越低，它包含的信息量就越大。所以我们刷短视频的时候，算法推荐的内容越来越精准，反而让我们获得的新信息越来越少。

输出（7 屏，45.5 秒）：

```
S1 hook  4.5s  你刷到的每一条 / 都是猜不到的
S2 quote 6.5s  信息的多少，不取决于你说了什么，而取决于对方猜不到什么
S3 scene 7.0s  八个格子 / 藏一个数字
S4 stat  6.0s  3 BITS
S5 scene 8.0s  越确定 / 越没有信息
S6 scene 7.5s  算法喂给你的 / 是你已经知道的
S7 outro 6.0s  真正的信息 / 总带着一点意外
```

注意：原文的「1948 年」「概率越低信息量越大」被压进了 kicker 和 body，
没有出现在标题里 —— **标题只留主张，事实放正文**。
