## 3. 质量指标与工具

衡量一张卡点表准不准，只看两个量（±150ms 内的平均起音包络）：

- **峰位**：包络峰相对拍点的偏移，越接近 0 越好（包络本身有约 +6ms 固有延迟）
- **峰背比**：拍点处平均包络 ÷ 全帧平均包络，越高说明能量越集中在拍点上

当前表：**峰位 0ms · 峰背比 5.53 · 网格抖动 5.8ms**。

换歌后照这两个数验收：**峰位偏离 > 20ms 或峰背比 < 2.5，就别硬卡**（说明这条音频没有可用节拍），
改用 `make-drum-track.mjs` 造基准轨，或每屏落在整秒。

工具：`refine-beats.py`（librosa DP，装一条 `uv pip install librosa soundfile` 即可）是正式方案。
**madmom 在 Windows 上编译不过、Beat-This 在这类重混响抽轨上会漏掉大量拍子，这两条路别再试了。**

## 6. 排片时长建议

一屏时长取 **8.503s 的整数分之一**，切点自然落在圈头：

| 除数 | 每屏时长 | 适合 |
|---|---|---|
| 1 | 8.503s | 信息密度低的大标题 / 结论页 |
| 2 | 4.251s | **最常用**，一句话一个论点 |
| 3 | 2.834s | 三段并列、列表逐条 |
| 4 | 2.126s | 快剪冲击、数据对比 |
| 6 | 1.417s | 只适合短标签，文字撑不住 |

`build.mjs` 会在 ±0.5s 内把 `dur` 推到最近的击打点；写成 4.2 / 4.3 都能落上，
**但 5.0 这种"半圈"值只会被挪到拍点，不会帮你对齐圈头。**

## 7. 怎么用

**日常（99%）什么都不用做**——`build.mjs` 默认读 `assets/beats.json`：

```bash
node scripts/build.mjs --story story.json --out out/story.html
# [build] 卡点：BPM 112.91 · 6/6 个切点落在击打上（1 处微调，最大位移 0.07s）
```

**查某个时间点的拍：**

```bash
node scripts/beats-info.mjs                # 概要 + 指纹校验
node scripts/beats-info.mjs --at 12.34     # → 最近的拍及偏差
node scripts/beats-info.mjs --snap 8.4     # → 对齐后的时长
node scripts/beats-info.mjs --check        # 只校验指纹，不匹配退出码 1
```

**需要重算（换了母带 / 新歌）：**

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv librosa soundfile
.venv/Scripts/python.exe scripts/refine-beats.py \
    --audio assets/bgm/vibe.mp3 --out assets/beats.json
```

它会打印旧表 / DP 原始 / 精修网格三者的峰位和峰背比，**看最后一行是否 0ms 附近、峰背比最高**。
`--dry-run` 只看不写。

## 8. 什么时候必须重跑

| 情况 | 动作 |
|---|---|
| 换歌 / 换母带 | 上面那条 `refine-beats.py` 命令 |
| `beats-info --check` 报 mismatch | 同上（音频被替换过） |
| 精修后峰背比 < 2.5 | 这条音频没有可用节拍，别硬卡；用 `make-drum-track.mjs` 造基准轨，或每屏整秒 |
| 只想改文案 / 版式 | **不用碰节拍表** |

---

## 9. 不要做的事

- ❌ 手改 `assets/beats.json` 的 `onsets`——它是测量结果，不是配置文件。
- ❌ 用 `0.059 + k × 0.53142` 自己推拍点——真实音头有 ±31ms 浮动。
- ❌ 把 `beat.mjs`（纯 Node 快速版）的输出直接当最终表——它的包络按帧起始对齐，
  整表**相位早 20–40ms**，等于一帧，肉眼就是"糊"。正式出片只用 `refine-beats.py` 的结果。
- ❌ 用"整段压成一张波形/频谱图"判断有没有鼓——会把瞬态糊成噪声墙，直接误判成"没有鼓"。
  至少放大到 2 秒看。
- ❌ 换歌后不重跑就 build——会打警告，但警告不等于卡点正确。
