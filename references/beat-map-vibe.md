# 曲目卡点档案 · vibe.mp3（神曲 / 开智小曲）

> **这份档案就是这个技能的"卡点真值"。** 做片子时 `build.mjs` 默认读 `assets/beats.json`，
> **不需要重新分析音频**，也不需要凭感觉对拍。下面是这套数字的来历、用法和禁忌。
>
> 最后校准：2026-10-18 · 工具 `scripts/beat.mjs` v2（周期 × 相位联合拟合）

---

## 1. 先看这四个数

| 项 | 值 | 含义 |
|---|---|---|
| **BPM** | **112.98** | 一拍 0.53106s |
| **循环** | **16 拍 = 8.497s** | 每圈开头是重拍（downbeat），全曲 19 圈 |
| **首拍** | **0.055s** | 第 1 拍不在 0 秒，`t=0` 是静音头 |
| **拍点数** | **302** | 已逐一吸附到真实音头，不是数学格子 |

**旧数据是错的**：`assets/beats.old96.json` 里的 96 BPM 是 v1 检测器的产物，
它的拍点里混进了八分音符和人声起音，间隔在 232–1335ms 之间乱跳。
96 与 113 差 17%，**第 20 拍就错开半拍**。不要再用它。

## 3. 这套数字是怎么验出来的（三条独立证据）

1. **拍点落音头**：302 个拍点前后 ±120ms 取平均高频起音包络，**峰值 100% 落在 0ms**
   （峰值强度 0.539，背景 0.03，10ms 分辨率）。
2. **画面跟着拍动**：成片抽逐帧亮度，127 个视觉脉冲到最近拍点的偏差**中位数 10ms**
   （30fps 一帧 33ms）；88.2% 在 ±50ms 内、98.4% 在 ±150ms 内；随机对齐的基线只有 18.8%。
3. **循环长度自洽**：19 个圈头间隔 8.451–8.520s，中位 8.497s；
   16 × 0.53106 = 8.497s，与外部资料给的"8.5 秒一个循环、113 BPM"吻合。
   另外用合成基准鼓轨（96BPM，鼓点精确到采样点）反向验证过检测器：返回 96.00 / 100% 落点。

## 6. 排片时长建议

一屏时长取 **8.497s 的整数分之一**，切点就会天然落在圈头，不用靠 build 去挪：

| 除数 | 每屏时长 | 适合 |
|---|---|---|
| 1 | 8.497s | 信息密度低的大标题 / 结论页 |
| 2 | 4.248s | **最常用**，一句话一个论点 |
| 3 | 2.832s | 三段并列、列表逐条 |
| 4 | 2.124s | 快剪冲击、数据对比 |
| 6 | 1.416s | 只适合短标签，文字撑不住 |

`build.mjs` 会在 ±0.5s 内把 `dur` 推到最近的击打点，所以写成 4.2 / 4.3 都能落上；
**但写成 5.0 这种"半圈"值，它只能挪到拍点上，不会帮你对齐圈头。**

## 7. 怎么用

**日常（99% 的情况）什么都不用做**——`build.mjs` 默认读 `assets/beats.json`：

```bash
node scripts/build.mjs --story story.json --out out/story.html
# [build] 卡点：BPM 112.98 · 6/7 处切屏对齐击打 · 最大位移 0.31s
# [build] 节拍层：58 个击打点（片长 59.56s）
```

**要查某个时间点的拍：**

```bash
node scripts/beats-info.mjs                # 概要 + 指纹校验
node scripts/beats-info.mjs --at 12.34     # 12.340s → 第 24 拍 12.269s（偏差 -71ms）
node scripts/beats-info.mjs --snap 8.4     # 8.400s → 8.552s
node scripts/beats-info.mjs --check        # 只校验指纹，不匹配退出码 1
node scripts/beats-info.mjs --json         # 机器可读
```

**在代码里读：**

```js
const b = JSON.parse(readFileSync('assets/beats.json', 'utf8'));
b.onsets      // [0.055, 0.626, ...] 302 个，秒
b.strong      // [0.055, 8.552, ...] 19 个圈头
b.period      // 0.53106
b.strongEvery // 16
```

## 8. 什么时候必须重跑

| 情况 | 动作 |
|---|---|
| 换歌 / 换母带 | `node scripts/beat.mjs --audio 新文件 --out assets/beats.json --strong-every 16` |
| `beats-info --check` 报 mismatch | 同上（音频被替换过） |
| `ratio < 1.25` 或 `confidence: low` | 这条音频没有可用节拍，别硬卡；用 `make-drum-track.mjs` 造基准轨，或改成"每屏整秒" |
| 只想改文案 / 改版式 | **不用碰节拍表** |

重跑后先看三个数：`ratio`（>1.25 才算可信）、`medianGapMs`（应 ≈ 531）、
`strong` 间隔（应 ≈ 8.5s）。三项都稳，再开始排片。

---

## 9. 不要做的事

- ❌ 手改 `assets/beats.json` 的 `onsets`——它是测量结果，不是配置文件。
- ❌ 用 `0.055 + k × 0.53106` 自己推拍点——真实音头有 ±46ms 浮动，推出来的会逐渐偏。
- ❌ 用 `beats.old96.json`，或任何 96 BPM 的结论。
- ❌ 用"24 秒压成一张波形/频谱图"判断有没有鼓——会把瞬态糊成噪声墙，直接误判成"没有鼓"。
  至少放大到 2 秒看。
- ❌ 换歌后不重跑就 build——现在会打警告，但警告不等于卡点正确。
